# Fidelity edge variants, version 2

The fidelity check ([v1.md](v1.md)) compares the simulator with a real lane on the baseline and two variants at opposite
edges of a parameter space. A new check runs on the newest parameter space that has edge variants and records that space
on the check, so a stored check keeps the variants it was accepted with. Version 2 covers parameter space 2
(`docs/parameter-space/v2.md`); `src/main/resources/fidelity/edge-variants-v2.json` ships the same sets as this record.

Version 2 is version 1 plus the three rules parameter space 2 adds, so the simulator's handling of them is compared with
the real services. Every version 1 override carries over with the same value and the same reason for any value that is
not the range edge (see [v1.md](v1.md)); version 1 stays as it is, so a check stored on space 1 replays unchanged.

- **`low`** sets the earliest Annihilate round to 1 and turns both switches off.
- **`high`** sets the earliest Annihilate round to 3 and turns both switches on.

The three rules are independent of every constraint of the space, so none of them is held off the edge. A check on this
space is refused with the reason `UNKNOWN_BASELINE` when the simulator's baseline rules lack one of the three keys.

## Validation

`FidelityEdgeVariantsTest` validates both sets of each version through the workbench's variant rules against that
version's parameter space, and checks that every key and value of each resource appears in the table of its record and
that the table lists nothing else.
