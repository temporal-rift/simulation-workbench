# Fidelity edge variants, version 4

The fidelity check ([v1.md](v1.md)) compares the simulator with a real lane on the baseline and two variants at opposite
edges of a parameter space. A new check runs on the newest parameter space that has edge variants and records that space
on the check, so a stored check keeps the variants it was accepted with. Version 4 covers parameter space 4
(`docs/parameter-space/v4.md`); `src/main/resources/fidelity/edge-variants-v4.json` ships the same sets as this record.

Version 4 is version 3 ([v3.md](v3.md)) plus the seven settings parameter space 4 adds, so the simulator's handling of
the faction-balance rules is compared with the real services. Every version 3 override carries over with the same value
and the same reason for any value that is not the range edge (see [v1.md](v1.md)), except the Prophet's victory objective,
whose range space 4 moves from [3, 5] to [2, 4]: its edges are now 2 and 4. Versions 1 to 3 stay as they are, so a check
stored on any of them replays unchanged.

- **`low`** sets one writing per era, turns the stabilization faction claims, the Tapestry absorption of a chain conflict
  and the Fate Contradiction paradox off, and sets the Rally declaration miss to -4, the Momentum declaration miss to -3
  and the Stabilize cost to -3.
- **`high`** sets three writings per era, turns the three switches on, and sets the three score values to 0 (no penalty).

The seven settings are independent of every constraint of the space, so none of them is held off the edge. The
stabilization thresholds apply only when the claims are on; `low` keeps them at their minimum even though the claims are
off there, so the variant stays a pure range edge. A check on this space is refused with the reason `UNKNOWN_BASELINE`
when the simulator's baseline rules lack one of the seven keys.

## Validation

`FidelityEdgeVariantsTest` validates both sets of each version through the workbench's variant rules against that
version's parameter space, and checks that every key and value of each resource appears in the table of its record and
that the table lists nothing else.
