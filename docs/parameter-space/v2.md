# Parameter space version 2

Version 2 is version 1 ([v1.md](v1.md)) plus three parameters for the Eraser and Prophet balance rules. Every
version 1 parameter, derived key, constraint and held-fixed entry is carried over unchanged, and version 1 stays
served exactly as before, so existing experiments and campaigns replay as they ran.

The search sets the new rules only through overrides of the parameters below, validated against this record like every
other parameter. The designer form sets `game.rules.annihilate-earliest-round` as a number and each of the two switches
with a `false` or `true` control. The configuration is `parameter-spaces/v2.json`.

## Added parameters

| Key | Type | Services | Baseline | Range | Step | Rationale |
|---|---|---|---|---|---|---|
| `game.rules.annihilate-earliest-round` | NUMBER | game-service | 2 | [1, 3] | 1 | The first round of an era in which Annihilate may be played; later is weaker for the Eraser. A play before it is rejected, and bots reselect from their remaining candidates |
| `game.rules.scoring.written-outcome-shields-annihilation` | BOOLEAN | game-service | `true` | `false`, `true` | | Whether an outcome written by a Prophet is shielded from annihilation |
| `game.rules.probability.erased-weight-to-written-outcome` | BOOLEAN | timeline-service | `true` | `false`, `true` | | Whether the weight of an erased outcome moves to the written outcome |

A boolean parameter has no range or step: its only values are `false` and `true`. An override of a boolean parameter
is `true` or `false`; a number for a boolean parameter, or a boolean for a numeric one, is refused with the reason
`WRONG_TYPE`. A campaign search treats a boolean parameter as a two-value axis, `false` then `true`.

A baseline rules document must carry all three keys at their baseline values for version 2 to apply to it.
At startup the workbench logs a warning that names the `rules-document` setting of each declared baseline that lacks
them; new campaigns and designer variants use the newest version, so such a baseline is refused when first used.

## Reading results

The faction-greedy Prophet bot always writes the leading outcome, so the play that the erased-weight rule enables
(writing the runner-up) does not appear in greedy-bot results. The greedy Eraser's plan of erasing the leader is close
to optimal. Compare a setting on and off rather than reading absolute win shares.
