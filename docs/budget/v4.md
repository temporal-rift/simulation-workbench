# Search budget record version 4

Status: proposed with search algorithm version 2 (temporal-rift/simulation-workbench#149). It supersedes version 3
([v3.md](v3.md)), which is unchanged, for the default search parameters of a new campaign; the confirmation duration of
version 3 still holds.

## What changes

A campaign no longer has a time budget. Earlier records called their hours a budget and the search stopped when they
were spent; the figure was meant as a target for how fast a campaign should run, and a time stop makes the short list
depend on the machine. From this version the search ends when its plan ends, and the hours below are a target that sizes
the default plan, measured on every run as `spentSeconds` and never enforced.

The plan is now exact. Version 3 counted a halving plan in which each round plays only the survivors of the round before.
Search algorithm version 1 did not play that plan: every later round also added new candidates, so its real game count
was higher than version 3 stated and it had no end of its own besides its time budget. Version 2 plays exactly the
halving plan.

## Search parameters

| Parameter | Value |
|---|---|
| `version` | `SUCCESSIVE_HALVING_V2` |
| `initialCandidates` | 32 |
| `screeningSeeds` | 2 |
| `eta` | 2 |
| `shortListSize` | 1 |

These are version 3's values (`search-budgets/v4.json`).

## Plan

Round `r` plays `nᵣ` candidates on `screeningSeeds × etaʳ` seeds, with `n₀ = 32` and `nᵣ₊₁ = ⌈nᵣ / 2⌉`; a candidate
plays only the seeds it has not played. The search ends after round 4, the first that keeps at most one candidate. A
screening seed is 110 games (55 cases on each of the two screening tables of criterion version 2).

| Round | Candidates | Seeds | New seeds per candidate | Games | Cumulative games |
|---:|---:|---:|---:|---:|---:|
| 0 | 32 | 2 | 2 | 7,040 | 7,040 |
| 1 | 16 | 4 | 2 | 3,520 | 10,560 |
| 2 | 8 | 8 | 4 | 3,520 | 14,080 |
| 3 | 4 | 16 | 8 | 3,520 | 17,600 |
| 4 | 2 | 32 | 16 | 3,520 | 21,120 |

21,120 games, every one played whatever its duration. At the simulator rate of version 3 (5,402 games an hour, 12 slots on
the reference spec) that is 3.91 hours, inside the target of about 4 hours. A busier or slower machine takes longer and
the search still plays the whole plan; the campaign reports the time it took.

## Limits

The plan screens 32 points of a 45-parameter space: the baseline and a Latin hypercube sample, without local refinement
around a good point. It is a screen, as in version 3.
